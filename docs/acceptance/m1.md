# M1 Pairing and Device Link acceptance

**Status:** BLOCKED pending one clean-commit real-Deck run.

Tracking: [M1 specification #20](https://github.com/Vectorking-50kg/s3-rlcd-deck/issues/20), [acceptance #31](https://github.com/Vectorking-50kg/s3-rlcd-deck/issues/31).

The acceptance command builds the current clean commit, safely programs and verifies both Deck
OTA application slots, validates the firmware and Companion embedded commit identities, starts
the real Companion, and uses the real Deck Setup page, pinned
TLS/WSS client, persisted Companion Profile, and management routes. It proves first Pairing,
Deck reboot reconnection, Companion stop/recovery, wrong-certificate rejection, incompatible
major rejection, trust revocation, and management/Device Hub authority separation. It also
links a same-commit Actions run in which both native macOS and Windows tray observations passed.

Raw evidence remains under ignored `.hil-results/`. Only the machine `summary.json` may be
copied to `docs/acceptance/evidence/`. The serial capture is allow-listed and redacted: Setup
access is replaced by a fixed marker, and credentials/certificates are never persisted.

Failures return non-zero and keep only the partial redacted capture and summary. Companion output,
preflight output, app-flash output, and serial evidence all pass the redaction gate. A compensating
cleanup restores Deck trust, closes Setup, returns the host to its original Wi-Fi, stops every
Companion process, and makes any cleanup failure fail the run. Host replay or fake adapters cannot
set the real Deck or native platform gates.

The current version-controlled report remains blocked until the result is produced from the
same clean commit as both firmware and Companion.
